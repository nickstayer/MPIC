# MPIC - Монитор Интеграции Почты и CRM

## Назначение

Приложение `MPIC` (Mail-CRM Integration Checker) представляет собой службу мониторинга, предназначенную для проверки корректности работы интеграции между почтовым ящиком и CRM-системой "Мегаплан".

Основная задача — автоматически отслеживать, создаются ли в Мегаплане сделки после получения писем от клиентов, и оперативно уведомлять ответственных лиц о сбоях и восстановлении работы интеграции.

## Принцип работы

1.  **Периодическая проверка**: Приложение запускается через заданные интервалы времени.
2.  **Анализ почты**: На каждом цикле оно подключается к указанному в настройках почтовому ящику (по протоколу IMAP) и получает информацию о письмах, пришедших после последней проверки (или последние 10 писем при первом запуске).
3.  **Запрос к CRM**: Затем приложение обращается к API Мегаплана и запрашивает список сделок, обновлённых/созданных после самого старого из новых писем (с запасом).
4.  **Проверка связи**: Система ищет сделку, контактные данные контрагента в которой (email) совпадают с адресом отправителя письма **и которая создана строго после получения письма**.
5.  **Определение статуса**:
    *   **Успех**: Если сделка найдена и была создана в течение заданного порогового времени после письма, интеграция считается работающей.
    *   **Предупреждение**: Если сделка найдена, но создана с задержкой, превышающей пороговое значение, система отправляет предупреждение.
    *   **Сбой**: Если в течение порогового времени соответствующая сделка не была найдена, система фиксирует сбой интеграции.

## Логика уведомлений

Система уведомлений разработана так, чтобы предоставлять актуальную информацию и избегать избыточных оповещений:

-   **Уведомление о сбое**: При первом обнаружении проблемы (письмо пришло, а сделка не создалась) система отправляет email-уведомление об ошибке. Чтобы избежать повторных оповещений по одной и той же проблеме, `Message-ID` письма сохраняется, и повторные уведомления по нему блокируются.
-   **Новый сбой**: Если после этого приходит *новое* письмо, которое также не приводит к созданию сделки, система отправит новое уведомление, так как это уже другая проблема.
-   **Уведомление о восстановлении**: Как только система фиксирует первую успешную интеграцию (сделку) после периода сбоев, она отправляет уведомление о восстановлении работы.
-   **"Тихий" режим**: После отправки уведомления о восстановлении система переходит в штатный режим и больше не отправляет уведомлений об успешной работе, пока не произойдет новый сбой.

Состояние системы уведомлений (информация о сбоях и отправленных оповещениях) хранится в файле `notification_state.json`.

## Конфигурация

Все параметры работы приложения настраиваются через **`Microsoft.Extensions.Configuration`** со следующими источниками (в порядке приоритета):

1. **`appsettings.json`** — основной файл конфигурации (обязательный, в корне проекта).
2. **User Secrets** — только в режиме Development (для локальной отладки).
3. **Переменные окружения с префиксом `MPIC_`** — например `MPIC_MpicSettings__Username`.
4. **Аргументы командной строки** — при ручном запуске.

Все runtime-настройки находятся в секции `MpicSettings` файла `appsettings.json`.

Пример структуры `appsettings.json`:

```json
{
  "MpicSettings": {
    "Username": "...",
    "Password": "...",
    "BaseApUrl": "https://crm.example.com/api/v3",
    "ConnectionString": "server=...;database=...",
    "LaunchTime": ["00:00", "08:00", "16:00"],
    "MaxTimeToCreateDealAfterLetter": 5,
    "RunIntervalMinutes": 60,
    "SkipReplyLetters": false,
    "MonitoredMailboxes": [
      { "Username": "...", "Password": "..." }
    ],
    "NotificationSettings": {
      "SmtpHost": "smtp.example.com",
      "SmtpPort": 465,
      "UseSsl": true,
      "SenderEmail": "...",
      "SenderPassword": "...",
      "RecipientEmail": "..."
    }
  }
}
```

### Дополнительные файлы конфигурации

В папке `Megaplan\` (копируется в выходную директорию) находятся:

- `Token/token.json` и `Token/token_exp_at.txt` — сохранённый токен авторизации Мегаплана.
- `Mapping/deal_mapping_rules.json` и `Mapping/employee_mapping_rules.json` — правила маппинга полей для нормализации данных.
- `Contacts/contacts.csv` — файл с контактными данными.

## Установка как Windows-служба

MPIC работает как **Windows-служба** (BackgroundService), используя `Microsoft.Extensions.Hosting.WindowsServices`.

### Предварительные требования

-   .NET 10 Runtime на целевой машине (скачать: https://dotnet.microsoft.com/download/dotnet/10.0)
-   Собранный бинарник (`MPIC\bin\Release\net10.0\publish\`) с обновлённым `appsettings.json`

### Установка (через PowerShell от имени администратора)

1.  Опубликуйте приложение:
    ```powershell
    dotnet publish C:\Git\MPIC\MPIC\MPIC.csproj -c Release -o C:\Services\MPIC
    ```
    *`appsettings.json` и папка `Megaplan\` будут скопированы автоматически из проекта.*

2.  Создайте службу:
    ```powershell
    New-Service -Name "MPIC" `
        -BinaryPathName "C:\Services\MPIC\MPIC.exe" `
        -DisplayName "MPIC — Mail to CRM Integration Monitor" `
        -Description "Проверяет создание сделок в Мегаплане после получения писем и уведомляет о сбоях/восстановлении" `
        -StartupType Automatic
    ```

3.  Запустите службу:
    ```powershell
    Start-Service -Name "MPIC"
    ```

4.  Проверьте статус:
    ```powershell
    Get-Service -Name "MPIC"
    ```

### Просмотр логов

Логи пишутся в папку `Logs` рядом с исполняемым файлом службы (например `C:\Services\MPIC\Logs\app_YYYYMMDD.log`).

По умолчанию логи также дублируются в консоль, но при работе как службы консоль недоступна — используйте файлы логов.

### Удаление службы

```powershell
Stop-Service -Name "MPIC" -Force
Remove-Service -Name "MPIC"
```

*Примечание: `Remove-Service` работает в PowerShell 7+; в Windows PowerShell (5.1) используйте `sc.exe delete MPIC`.*
